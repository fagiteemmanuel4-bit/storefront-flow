## Navigation preservation checklist

The new four mobile destinations are **Sell**, **Products**, **Search**, and **Menu**. These are visual entry points, not permission changes:

- Sell → `/pos` (preserve mode-aware Sell/alternate workspace affordances).
- Products → `/products` (mode-specific catalogue labels remain contextual).
- Search → existing `QuickFind` interaction (no route change).
- Menu → every remaining existing destination and action, respecting current role, plan, business-mode and staff-session filtering.

Desktop/tablet navigation must preserve the same destinations in the sidebar. Do not flatten away the current mode-aware navigation or expose hidden links to roles that cannot access them. Preserve store/branch switching, online/offline indicators, queued sale status, updates, notifications, security, calculator and sign-out.

## Feature-map validation required during implementation

For each module, compare this map with the actual rendered page and source before restyling:

1. Enumerate every visible control, nested tab, filter, sort, bulk action, modal, sheet, confirmation and empty/error/loading state.
2. Record every role/permission/plan condition and every business-mode conditional.
3. Confirm every action still calls the same handler and every form submits the same payload.
4. Keep keyboard scanner focus/capture, camera permissions, printer connections, exports and print layouts behaviorally unchanged.
5. Update this map if source inspection finds an additional capability; never delete a capability to make the new design fit.
